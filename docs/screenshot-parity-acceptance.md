# 截图对齐验收矩阵

基线：[实现方案](screenshot-parity-implementation.md)。本表定义验收要求；当前实现、已运行证据和剩余缺口见[实施状态](screenshot-parity-status.md)，不能仅凭本表判断完成。

所有截图数量以实际库和实际调用统计替代，不硬编码；配色沿用当前主题。桌面主布局以截图所在的约1280像素宽度为参考，同时检查宽屏和窄窗口可用性。不可见部分采用项目现有交互样式。

| 编号 | 对照 | 验收场景 | 通过条件 |
| --- | --- | --- | --- |
| UI-01 | 图2–4侧栏 | 重排分组并逐一进入页面 | 分组、入口与截图对应；现有旧链接、刷新与导航状态有效；自定义角色真实显示 |
| UI-02 | 图2顶栏 | 查看出口和连接异常 | 真实默认出口/任务出口不混淆；未配置和失效说明准确 |
| DASH-01 | 图2快速开始 | 输入目标并开始；重复请求同次提交 | 真正创建任务，继承模型/预算/规则，幂等提交不多建；失败有原因 |
| DASH-02 | 图2阶段按钮 | 选择限定阶段模板 | 创建限定目标任务；能力未配置时清楚标识；不能只是按钮变色 |
| DASH-03 | 图2系统资源 | Docker及二进制读数对照 | 容器或进程口径明确；CPU/内存、限额、单位和采样时间正确 |
| DASH-04 | 图2统计 | 已知任务、发现、资产及Token记录 | 各卡片及图表与真实聚合一致，空库不显示宣传数据 |
| KB-01 | 图3 | 分类、类型、分档、正文/已验证筛选、搜索 | 条件组合和分页正确，显示真实命中数，清空条件恢复 |
| KB-02 | 图3条目 | 打开正文、查看来源与验证证据 | 正文不是占位；适用条件、来源/版本、验证与发布状态分别可追溯 |
| KB-03 | 图3复用 | kb_search、页面浏览、kb_get及请求重试 | 仅真实取用计量；同一调用重试不重复计数；调用次数不当作成功次数 |
| KB-04 | 知识生命周期 | 候选、审核、发布、撤销、正文变更 | 候选有来源；默认执行检索只含有效已发布已验证条目；撤销立即生效；正文新版本需重新判断验证 |
| KB-05 | 无自定义Agent依赖 | 手工导入和发布，再用内置角色取用 | 不要求新建 curator/verifier；沿用现有报告/复测能力，不改自定义配置 |
| CVE-01 | 图5 | 全量官方数据导入、重启后离线搜索 | 实际语料非样本占位；版本/计数可核对；断网可查编号、产品及描述 |
| CVE-02 | 图5更新 | 自动导入新记录、修改、撤回状态 | 未打开页面也同步；索引与年份统计更新；保留来源状态和参考链接 |
| CVE-03 | 图5更新 | 同步中断、重复批次、服务重启、错过增量 | 重跑无重复；游标不越过未提交数据；旧库继续可查；补齐遗漏 |
| CVE-04 | 图5更新状态 | 自动开关、立即更新、计划任务冲突 | 作业互斥；显示最近检查/成功、下次检查和各类计数；设置持久化 |
| CONTENT-01 | 图1模板数据 | 导入真实Nuclei快照、实际引擎加载 | 有模板文件及索引、来源/版本/许可记录；校验失败不冒充可用；运行结果可追溯 |
| CONTENT-02 | 图4技能目录 | 遍历新增技能并执行对应工作流 | 正文、输入输出、依赖与必要资源齐备；可在Linux复现；无空目录/重复条目凑数 |
| CONTENT-03 | 图3武器库 | 逐类别抽查实际内容与验证记录 | 有实质材料、适用条件、出处、测试依据和修复/检测信息；不是CVE描述批量改名；未验证不标已验证 |
| CONTENT-04 | 内容分发 | 离线重建索引、更新失败与回退 | 来源材料和清单足够复现；失败保留上版；历史任务引用旧版本仍可查 |
| SKILL-01 | 图4标签 | 目录树、分类筛选、编辑、导入、使用统计 | 保留原正文和关联；分类持久化；未分类明确；真实调用账本可查 |
| FIND-01 | 图6 | 严重性、搜索、展开和详情 | 截图对应行结构清楚，真实过滤；报告、证据、处置及复测仍可用 |
| AGENT-01 | 图7内置角色 | 查看编辑与资源绑定 | 原key/数据引用有效；卡片真实计数；不强制伪造14角色或资源数量 |
| EGRESS-01 | 图1/2代理 | 多任务各自租约和出口 | HTTP/HTTPS/SOCKS5实际可用；任务出口不串用；目标/LLM/搜索代理区分 |
| EGRESS-02 | 代理故障 | 健康检查失败、切换、无可用代理 | 切换有记录；默认故障暂停；只按显式设置直连回退；出口状态符合真实路径 |
| SESSION-01 | 图8 | 接入HTTP/PHP会话并关联任务 | 真正适配对应类型；宿主、心跳、状态、归属可核验；SSH不能代替 |
| SESSION-02 | 图8操作 | 调用适配器支持操作并查看结果 | 请求/结果可追踪；无能力或失效时明确失败；重复提交与超时有一致处理 |
| SESSION-03 | 图8拓扑 | 主机、网段、会话、隧道、凭据变化 | 节点与边来自真实关系；任务筛选正确；断开和失效更新到UI；不凭同网段捏造链路 |
| SESSION-04 | 图2侧栏C2/WebShell | 独立管理入口及兼容声明 | 各入口有实际数据/接入功能；明确支持的协议和操作；不能仅用空页或SSH称为完成 |
| WORKER-01 | 内网变体 | 有效/无效会话、有效/失效凭据、跨任务引用 | 只有满足任务归属和可用条件才切换；资源共用；回写事实与生命周期不破坏 |
| OPS-01 | Linux交付 | Compose冷启动、已有数据升级 | 依赖、持久化和内容准备步骤可复现；升级不覆盖用户配置或自定义Agent |
| OPS-02 | 持久化 | 重启、备份恢复、应用回退 | 数据、技能、内容版本和同步状态可恢复；不清空新表作为回退手段 |
| REG-01 | 原有功能 | 已有任务、流量、报告、复测、审批、日志 | 功能与数据可访问，关键权限/规则和配置不丢失 |

验收记录应包含：应用提交号、Linux/容器版本、实际硬件资源、内容批次、工具/适配器版本、测试数据来源、运行结果和失败项。所有条目以真实运行记录判定；文档创建、来源调研和界面存在均不能单独判定通过。
